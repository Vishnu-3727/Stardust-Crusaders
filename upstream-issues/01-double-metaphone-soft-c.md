**Title:** Double Metaphone codes every soft C as `K` and skips the following
letter — `cell` and `sell` do not match

---

`DMetaphone` fails on the case the algorithm exists to handle: exact
homophones that differ in spelling. Every `C` pronounced /s/ is coded `K`, and
the cursor advances one character too far, dropping the letter after it.

```python
>>> import fuzzy
>>> m = fuzzy.DMetaphone()
>>> m('cell'), m('sell')
([b'KL', None], [b'SL', None])       # expected both [b'SL', None]
>>> m('cent'), m('sent')
([b'KNT', None], [b'SNT', None])     # expected both [b'SNT', None]
>>> m('cite'), m('site')
([b'KT', None], [b'ST', None])       # expected both [b'ST', None]
>>> m('cede'), m('seed')
([b'KT', None], [b'ST', None])       # expected both [b'ST', None]
```

Lawrence Philips' Double Metaphone codes soft C as `S`. Some more:

| input | fuzzy | expected |
|---|---|---|
| `cent` | `KNT` | `SNT` |
| `city` | `KT` | `ST` |
| `ciao` | `K` | `S` (secondary `X`) |
| `cyst` | `KST` | `SST` |
| `ceiling` | `KLNK` | `SLNK` |

Every value in the "expected" column was checked against the `metaphone`
package on PyPI (`from metaphone import doublemetaphone`), not asserted from
the algorithm description.

## Cause

`src/double_metaphone.c`, in `case 'C':` — the `CC` test around line 384:

```c
/* double 'C', but not if e.g. 'McClellan' */
if (StringAt(original, current, 2, "CC", "")
    && !((current == 1) && (GetAt(original, 0) == 'M')))
{                                     /* <-- this brace, and its partner */
    /* 'bellocchio' but not 'bacchus' */
    if (StringAt(original, (current + 2), 1, "I", "E", "H", "")
        && !StringAt(original, (current + 2), 2, "HU", ""))
      {
          ...
          current += 3;
          break;
      }
}                                     /* <-- ...and this one */
else
  {	  /* Pierce's rule */
  MetaphAdd(primary, "K");
  MetaphAdd(secondary, "K");
  current += 2;
  break;
  }
```

In the reference implementation the inner `if` is not braced, so `else` binds to
it — Pierce's rule is the fallback for a `CC` **not** followed by `I`/`E`/`H`.
With the braces, `else` binds to the **outer** `if` and therefore fires for
every `C` that is not part of a `CC`.

Two consequences:

1. `MetaphAdd(primary, "K")` runs for all soft C.
2. `current += 2` consumes the vowel after the C — which is why `ciao` codes as
   a bare `K` and `cent` loses nothing visible but `city` drops the `i`.

It also makes three later branches in the same `case` unreachable except on the
narrow path where the outer test matched and the inner one did not:

* `if (StringAt(original, current, 2, "CK", "CG", "CQ", ""))`
* `if (StringAt(original, current, 2, "CI", "CE", "CY", ""))`  ← the soft-C rule
* the final `MetaphAdd(primary, "K")` with the `mac caffrey` / `mac gregor`
  cursor handling

## Fix

Remove the braces so `else` binds to the inner `if` again:

```c
if (StringAt(original, current, 2, "CC", "")
    && !((current == 1) && (GetAt(original, 0) == 'M')))
    /* 'bellocchio' but not 'bacchus' */
    if (StringAt(original, (current + 2), 1, "I", "E", "H", "")
        && !StringAt(original, (current + 2), 2, "HU", ""))
      {
          ...
      }
    else
      {	  /* Pierce's rule */
        ...
      }
```

or, better, keep the braces and move the `else` block inside the outer `if`,
which says the same thing without depending on the dangling-else rule.

**Please note this is a behavior change.** Anyone with stored codes generated by
this library will see them stop matching newly generated ones for any word
containing a soft C. It probably wants a major version bump and a note in
CHANGES.rst rather than a patch release.
